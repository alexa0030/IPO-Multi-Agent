# 比赛与简历表述建议

## 推荐项目名

基于证据账本与多智能体协作的港股 IPO 尽调系统

## 项目差异化

普通 PDF Agent 常见流程是“切块、向量检索、生成摘要”。本项目更适合投资尽调场景的差异点是：

1. 报表原文、标准化事实、确定性计算和 Agent 结论分层；
2. Finding 必须引用 Evidence ID，可回到 PDF 页码或真实 URL；
3. 财务 Agent 内部调用提取、指标、基础风险和法证规则工具；
4. 投资委员会负责跨 Agent 冲突，Skeptic 只针对关键缺口补证；
5. 补证最多一轮，无搜索密钥时保留未解决问题，不生成模拟结果；
6. 输出是可复核的 Markdown 投资报告和 Excel 底稿，不以聊天回答为终点。

## 简历 bullet（可按实际面试篇幅选用）

- 设计港股 IPO 多智能体尽调系统，使用 LangGraph 编排研究经理、招股书、财务、行业、投资委员会与 Skeptic Agent，并通过结构化 Evidence/Finding/Challenge 契约实现跨 Agent 证据传递。
- 构建页级 PDF 证据底稿与财务事实层，使用 Python 确定性计算 32 项指标并执行 20 条财务法证规则，使报告结论可追溯至招股书原页和计算来源。
- 实现有界反思与补证机制：投资委员会检测业务与财务结论冲突，Skeptic 最多提出 3 项挑战并触发 1 轮真实网络检索；离线状态下显式保留证据缺口，避免伪造新闻和引用。
- 在 504 页真实港股申请版本上完成离线与 Qwen3.5-4B 双链路回归，提取 13 张报表、462 条财务事实、33 条模型附注和 32 项指标，生成 Markdown、Excel、Evidence Ledger 与 Agent Trace。

最后一条中的数字是单一样本回归结果。若未来样本或算法变化，应同步更新，不能表述为通用准确率。

## 面试讲解顺序

1. 先讲问题：数百页招股书、跨章节口径和引用复核成本；
2. 再讲约束：模型不能负责算数，也不能在没有来源时补事实；
3. 展示 Evidence → Finding → Challenge → Report 的数据流；
4. 用一项财务异常说明从 P 页原表到 Python 计算再到风险挑战的链路；
5. 最后讲边界与下一步评测，而不是声称替代分析师。

## 不应夸大的部分

在没有多公司人工标注集、OCR 兜底、法律/监管数据源验证和分析师复核前，不应写“审计级准确率”“全自动投资决策”“替代投行尽调”或未经测量的准确率百分比。
