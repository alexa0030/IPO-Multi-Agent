# 简历与面试表述

## 推荐项目名

**港股 IPO Evidence-grounded Multi-Agent 尽调平台** ｜ 项目负责人

## 简历版本（推荐）

- 面向一级市场投研场景，设计并实现港股 IPO 自动化尽调平台，使用 LangGraph 编排 Research Manager、财务、公司、行业、法律及 Reviewer/Skeptic 等角色，覆盖招股书解析、并行研究、反证复核与报告交付闭环。
- 将 PDF 原表、标准化财务事实、确定性指标和模型结论分层，通过 Pydantic `Evidence / Finding / Challenge` 契约建立可审计证据账本；财务指标与风险规则由 Python 计算，模型仅负责解释，避免数字幻觉和悬空引用。
- 在 504 页港股申请版本回归案例中提取 13 张报表、468 条财务事实与 29 项指标，并配置 20 条财务法证规则；交付 Markdown 报告、Excel 底稿、Evidence Ledger、Agent Trace 与 SQLite 审计数据。
- 建立 4 公司版本化评测框架和 135 项自动化测试，覆盖财务抽取、证据完整性、搜索降级、跨 Agent 合约、Reviewer/Skeptic 闭环及报告交付，并验证 Python 3.10–3.12 运行环境。

> 数字只描述当前仓库与单一已人工核验回归案例，不应表述为跨公司准确率。其余三个案例仍需补充人工 gold labels 后，才适合对外发布泛化指标。

## 30 秒项目介绍

传统 PDF Agent 往往把招股书切块后直接总结，但尽调最难的是数字不能算错、结论必须能回页码、不同研究员的判断还会冲突。我做的系统把确定性财务计算和大模型研究分开：代码负责三表、指标和规则，Agent 负责解释与跨来源验证；所有 Finding 必须引用 Evidence，Skeptic 只针对重大缺口触发一轮补证，最后输出可复核的报告和 Excel 底稿。

## 面试时主动说明的边界

- 当前是 Engineering MVP，不替代投资、审计或法律判断。
- 已人工标注并可量化评分的是 1 个开发回归案例；另外 3 个案例已完成清单与数据切分，但 gold labels 尚未补齐。
- 扫描型 PDF、复杂跨页表格和外部网页访问仍可能需要人工复核。
